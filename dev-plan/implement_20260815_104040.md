# implement_20260815_104040.md

작성 일시: `2026-08-15 10:40:40 KST`

이 문서는 AI Systems Atlas의 실제 배포·실행 경계를 기준으로 보안 항목을 다시 선별하고, 현재 기능을 깨뜨리지 않는 순서로 보강하기 위한 작업 문서다.

## 개발 목적

- 공개 Vercel 정적 앱과 로컬 D1·OAuth 통합 앱을 서로 다른 보안 경계로 취급한다.
- 현재 공개 배포에 존재하지 않는 서버 위험을 배포 장애로 과장하지 않으면서, 로컬 통합 앱의 실제 위험은 차단한다.
- OpenAI API Key 없이 `codex login` OAuth를 사용하는 현재 구조와 로컬 단일 사용자 사용성을 유지한다.
- 한 번에 한 보안 항목씩 구현·검증해 회귀가 생기면 해당 Phase 안에서 원복할 수 있게 한다.

## 개발 범위

- 로컬 통합 앱의 loopback 기본 바인딩과 브라우저 same-origin 변경 요청 보호
- 로컬 직접 실행과 인증 프록시 실행을 구분하는 fail-closed 노출 정책
- Codex 자식 프로세스 환경 변수 allowlist와 출력 비밀 유출 차단
- production에서 test mode 우회 차단, 오류 응답 최소화, canonical origin 처리
- 취약 의존성의 호환성 검증 후 패치 업데이트
- 공개 Vercel 정적 앱의 CSP·클릭재킹 방어와 배포 gate 운영 검증
- 원격 동적 앱을 실제로 공개할 때만 적용할 업로드·인증 추가 방어의 조건부 기준 확정

## 제외 범위

- OpenAI 유료 API, API Key, LightRAG, 외부 RAG 또는 새 LLM 서버 도입
- 공개 Vercel 앱에 D1, API Route, Codex/GitHub OAuth 런타임 배포
- 로컬 단일 사용자 모드의 모든 읽기 화면에 로그인 강제
- 로컬 D1 원본·비공개 문서·OAuth 토큰을 Git 또는 공개 JSON에 포함
- Markdown parser, 그래프 데이터, 노드·관계 알고리즘, GUI 기능 변경
- legacy 10,825개 작업 실행, 853문서 전체 재처리, D1 데이터 마이그레이션
- 보안과 무관한 리팩터링 또는 신규 외부 보안 서비스 도입

## 문서 기반 제약 사항

- 공개 Production은 `dist-vercel`의 정적 파일과 검증된 `public/atlas/*.json`만 배포하며 Function·D1·내부 API·OAuth를 포함하지 않는다.
- 전체 D1과 private 저장소 문서는 로컬 통합 앱에만 존재한다.
- Codex는 `@openai/codex-sdk`와 기존 `codex login` OAuth 세션만 사용한다.
- 브라우저, D1 일반 테이블, 로그, 공개 산출물에 OAuth 토큰이나 내부 IPC 값을 남기지 않는다.
- 로컬 기본 사용자는 로그인 없이 자기 PC의 문서·그래프를 관리할 수 있어야 한다.

## 재검토 결론

현재 공개 Vercel 앱에서 확인된 직접 악용 가능한 Critical·High 취약점은 없다. 기존 High 판정 대부분은 `npm start`로 실행하는 로컬 동적 앱을 외부에 노출했을 때의 위험이다. 따라서 전체 읽기 API에 즉시 로그인을 강제하는 방식이 아니라, **기본 loopback 격리 + same-origin 변경 보호 + 원격 프록시 모드의 명시적 fail-closed**가 현재 프로젝트에 맞는 수정이다.

| 기존 항목 | 현재 필요성 | 최종 처리 방향 |
|---|---|---|
| SEC-H01 변경 API fail-open·외부 바인딩 | 필수 | 서버를 loopback에 고정하고 cross-site 변경 요청을 거부한다. 원격 노출은 인증 프록시 모드에서만 허용한다. |
| SEC-H02 로컬 D1 읽기 공개 | 조건부 필수 | loopback 로컬 모드에서는 기존 읽기 UX를 유지한다. 인증 프록시 모드에서만 전체 D1 읽기를 인증하고, 공개 읽기는 정적 JSON으로 분리한다. |
| SEC-H03 Codex 환경 denylist | 최우선 필수 | 비신뢰 Markdown이 Codex에 전달되므로 최소 환경 allowlist와 결과 secret guard를 적용한다. |
| SEC-H04 취약 의존성 | 단기 필수 | 공개 정적 runtime의 직접 취약점으로 과장하지 않되, local runtime·build host를 위해 호환성 검증 후 패치한다. |
| SEC-M01 multipart 선파싱 | 조건부 | loopback에서도 조기 `Content-Length` 검사는 적용한다. streaming parser·rate limit은 원격 업로드가 실제 활성화될 때만 도입한다. |
| SEC-M02 CSRF | 필수 축소 적용 | local 로그인 유무와 무관하게 모든 변경 route에서 `Origin`·Fetch Metadata를 검사한다. CSRF token은 cookie 인증 프록시를 실제 사용할 때만 적용한다. |
| SEC-M03 CSP·frame 보호 | 권장 | 현재 XSS sink는 없지만 저비용 방어이므로 공개 정적 앱과 로컬 앱에 호환 가능한 정책을 검증 후 적용한다. |
| SEC-M05 production test bypass | 필수 | `ATLAS_TEST_MODE`를 실제 test process에서만 허용하고 production 시작 시 즉시 실패시킨다. |
| SEC-L01/L02 오류·Host 처리 | 권장 | 공용 error mapper와 canonical origin으로 작은 범위에서 정리한다. |
| SEC-L03 CI와 Vercel gate | 운영 확인 | source visibility CI는 이미 존재한다. Vercel 배포의 required 선행 gate 여부만 설정·증적으로 확인한다. |

## 현재 적용하지 않을 과도한 대응

- 공개 정적 앱에 OAuth 로그인이나 서버 세션을 추가하지 않는다.
- 로컬 loopback 전용 읽기 API에 일괄 로그인을 강제하지 않는다.
- 단순 파일 크기 제한을 위해 즉시 새 multipart 의존성을 추가하지 않는다.
- `npm audit fix --force`로 호환성 검증 없이 major/preview 조합을 변경하지 않는다.
- GitHub Actions 검증이 이미 존재하는데 동일 검증을 중복 구현하지 않는다.

## Phase 1. 로컬 네트워크·브라우저 변경 요청 경계

### 목표

- 로컬 무로그인 UX는 유지하면서 LAN 접근, DNS/Host 오용, cross-site 변경 요청을 기본 차단한다.

### 구현 태스크

- [x] vinext CLI의 실제 host 옵션을 확인하고 dev·production launcher 모두 `127.0.0.1`에 명시적으로 바인딩한다.

## 조건부 후속 과제

다음 항목은 로컬 통합 앱을 OAuth reverse proxy 뒤에서 여러 사용자에게 실제 공개할 때만 별도 계획으로 시작한다.

- [ ] streaming multipart parser 또는 proxy-level body/part/concurrency 제한
- [ ] cookie session을 사용할 경우 CSRF token과 cookie 속성 검증
- [ ] 사용자·tenant별 D1 visibility와 server-side authorization
- [ ] 사용자/IP별 rate limit과 보안 이벤트 감사 로그
- [ ] 프록시 identity header stripping·attestation·허용 사용자/역할 검증

현재 Vercel 정적 공개 앱만 운영하는 동안에는 이 후속 과제를 구현하지 않아도 된다.
