# implement_20260808_222109.md

작성 일시: `2026-08-08 22:21:09 KST`

이 문서는 OAuth 기반 Codex 관계 보강 대기열을 일괄 실행하지 않고, **원문에 관계가 명시된 청크만 점수화·검토·선별 실행**하기 위한 개발 범위를 고정한다. 목표는 노드 수를 인위적으로 늘리는 것이 아니라, 근거가 있는 의미 관계를 안전하게 추가해 그래프의 연결 품질을 높이는 것이다.

## 개발 목적

- 현재 provider 대기 작업에서 관계 생성 가능성이 높은 청크를 재현 가능하게 찾는다.
- 운영자가 후보의 원문 근거와 제외 사유를 확인한 뒤 소량 작업만 실행할 수 있게 한다.
- Codex 결과가 관계를 만들지 않아도 정상 결과로 기록하며, 사실 관계·D1 무결성·기존 그래프를 보존한다.

## 개발 범위

- 현재 통합 runtime generation(`codex-sdk-0.146.0+atlas-runtime.1`)의 `queued` enrichment job만 후보로 조회한다.
- 기존 job input의 evidence block·노드·문서 메타데이터를 사용해 결정적(LLM 미사용) 관계 후보 점수를 계산한다.
- 관계 동사, 온톨로지 허용 관계, 두 개 이상의 식별 가능한 대상, 링크·경로·Phase/Task 참조, 독립 근거 수를 점수와 사유로 노출한다.
- 목차, 변경 이력, 링크 모음, 체크박스만 있는 행, 반복 템플릿 제목, 코드/배지/설치 명령만 있는 청크는 감점 또는 제외한다.
- 대시보드에서 상위 후보·점수·원문 근거·예상 관계 유형·제외 사유를 읽기 전용으로 검토하고, 최대 10개를 선택해 기존 선별 실행 경계로 넘긴다.
- 10개 실행 후 Codex 결과·신규 관계 수·거절 사유·D1 감사 결과를 기록하고 다음 25개 확대 여부를 판단한다.

## 제외 범위

- 구형 provider 대기열 10,825개를 현재 runtime으로 자동 변환·실행하지 않는다.
- 10,900개 대기열을 일괄 실행하지 않는다.
- OpenAI API Key, LightRAG, 외부 벡터 DB, 별도 관계 추출 서비스는 도입하지 않는다.
- 점수만으로 관계를 D1에 저장하거나 기존 규칙 관계를 수정·삭제하지 않는다.
- Gold Graph·기본 그래프 연출·3D renderer의 시각 디자인을 변경하지 않는다.
