# implement_20260808_234515.md

작성 일시: `2026-08-08 23:45:15 KST`

이 문서는 Codex 관계 후보의 점수를 낮춰 실행 수를 늘리는 대신, Markdown 파서와 enrichment input이 **근거 있는 의미 앵커 노드 쌍**을 제공하도록 보강하는 개발 범위를 고정한다. 구현 후에도 Codex 실행·job claim·D1 재인덱싱은 자동으로 시작하지 않는다.

## 개발 목적

- 현재 queued job의 `high 0` 원인을 점수 임계값이 아닌 의미 노드 문맥 부족으로 해결한다.
- README·개발계획의 서비스, API, 파일, 도구, Phase/Task를 근거가 있는 앵커로 제공해 Codex가 관계 대상을 추측하지 않게 한다.
- 실제 의미 관계의 양끝·방향·근거를 먼저 결정적으로 검증하고, 그 뒤에만 OAuth Codex가 관계 유형을 검토하게 한다.

## 검토 기준선

현재 integrated provider의 queued job 68개를 D1 변경 없이 점수화한 결과다.

| 항목 | 수량 | 판단 |
|---|---:|---|
| README 기반 job | 61 | 대부분 document/repository만 input node로 제공됨 |
| 개발계획 기반 job | 7 | Phase/Task는 있으나 상태 문장 비중이 높음 |
| 양쪽 의미 노드 0개 | 42 | 관계 대상을 확인할 수 없음 |
| 의미 노드 1개 | 24 | 한쪽 대상만 확인됨 |
| 의미 노드 2개 이상 | 2 | 그중 1개는 상태·검증 문장이라 자동 실행 부적합 |
| high / review / excluded | 0 / 64 / 4 | 임계값 완화로 해결하면 안 됨 |

### 원인 결론

- 현 `selectNodesForChunk`는 같은 block에 이미 생성된 노드와 document/repository/plan을 전달한다.
- `image_proxy`, `research_proxy`, `Android`, `카카오톡`, API path처럼 문장에 명시된 대상이 **그래프 노드로 생성되지 않았거나 해당 chunk input에 포함되지 않았다.**
- 따라서 `calls`, `tests`, `produces` 같은 동사 신호만 있고, 저장 가능한 source·target pair가 없다.
- 점수 기준을 68점 이하로 낮추면 상태 문장과 문서 구조가 다시 `high`로 올라와 기존 수동 시험의 품질 문제가 반복된다.

## 개발 범위

- Markdown block에서 서비스/컴포넌트, API, 파일, 기술, Phase/Task의 **의미 앵커**를 결정적으로 추출한다.
- 앵커는 source-local node, 기존 같은 문서 node, 또는 범위가 확인된 shared technology node에만 해석한다.
- enrichment chunk에는 관계 판단에 필요한 앵커를 우선 제공하고 document/repository node는 컨텍스트로만 유지한다.
- 후보 점수는 `두 앵커 + 명시 동사 + 방향 판별 + 현재 block evidence`를 모두 충족할 때만 `high`로 승격한다.
- `/dashboard` 후보 패널에 앵커 수, source/target, 앵커 해석 사유를 최소 정보로 표시한다.
- 68개 현 대기 job을 대상으로 **읽기 전용 재점수화**만 수행한다.

## 제외 범위

- 점수 임계값을 낮춰 high 후보를 인위적으로 늘리지 않는다.
- 전체 853문서 재인덱싱, 현재 68개 job 재생성, legacy 10,825개 변환·실행을 하지 않는다.
- Codex SDK 실행, job claim, D1 관계 쓰기, 자동 backup 또는 자동 배포를 하지 않는다.
- OpenAI API Key, LightRAG, 외부 RAG/벡터 DB, 새 관계형 DB를 추가하지 않는다.
- 현재 그래프 GUI·Gold Graph·성운/별자리/궤도 연출을 변경하지 않는다.
- 온톨로지에 `receives_from` 등 새 relation type을 추가하지 않는다. 현재 계약으로 방향을 확정할 수 없는 문장은 review에 남긴다.

- `SemanticAnchor` resolver를 추가해 component/API/file/package/Phase·Task를 evidence block 안에서만 해석한다. 일반 document/repository/section/heading은 관계 endpoint가 될 수 없다.
