### OAuth 레거시 보강 경로 검토

`app/lib/llm/oauth-client.ts`와 `oauth-proxy-enrichment.ts`는 현재 웹 라우트·Connector 실행 경로에서 import되지 않는다. 현재 서비스는 로컬 Codex Connector를 보강 실행 경로로 사용하며, OAuth 프록시는 쓰기 접근 경계 검증에만 필요하다. 따라서 레거시 OAuth 보강 모듈과 `OAUTH_*` 환경 변수는 기본 경로에서 격리된 상태로 유지하고, 제거는 별도 호환성 정리 변경에서 수행한다.

### 수동 검토·환경 대기

- 발광 UX 후보는 `preview=luminosity-v2`에서만 유지한다. 사용자 시각 검토 전에는 기본값 승격이나 `preview` 분기 제거를 하지 않는다.
- 브라우저에서 별자리·성운·궤도, 축소 화면, reduced-motion, 키보드 팝오버 및 스크린 리더 안내를 확인해야 한다.
- OAuth 프록시 검증에는 실제 staging URL, 신뢰 프록시의 사용자 식별 헤더 제거·재주입 구성, 그리고 해당 환경에 대한 실행 승인이 필요하다. 준비 후 `npm run verify:oauth -- --base-url=<staging-url>`을 실행한다.

## 잔여 리스크 / 후속 과제

- 운영 OAuth 프록시 검증은 staging 환경과 별도 사용자 승인이 있어야 완료할 수 있다.
- 대용량 원문은 D1 대신 R2 분리 여부를 실제 사용량 기준으로 재검토한다.
- 32비트 `stableKey` 식별자 충돌 위험, 다중 업로드 부분 반영, D1 미바인딩 시 메모리 폴백은 별도 안정성 하드닝 범위로 다룬다.
